## 3. 建议实施顺序

按"依赖少、用户感知强、风险低"排序：

```
① 设置体系（含显示隐藏文件/扩展名）
     ↓ 依赖：无。但它提供"显示扩展名"等基础能力，后续功能都会用到
② 详情窗格
     ↓ 依赖：仅需当前选中项
③ ~~导航窗格~~（已完成）
     ↓ 依赖：设置里的显示开关
④ 预览窗格（优先级最低，待定，可能不做）
     ↓ 依赖：选中项（与②同源）
⑤ ~~搜索与筛选~~（已完成）
     ↓ 依赖：无强依赖，但结果列需要列表支持动态列
⑥ 树的网络节点、拖放联动
```

**为什么设置排第一**：它不只是"加个界面"——`View.ShowHidden` 与 `View.ShowExtensions` 会改变枚举与显示逻辑，
是后续所有功能的公共基础。先做可以避免后面反复改动。

## 4. 跨文档的共性决策

这些决策在多篇文档中重复出现，集中说明：

| 决策 | 内容 | 出处 |
| --- | --- | --- |
| 不写 `%APPDATA%` | 配置、日志、临时文件全部在 `<exe>\data` | SETTINGS §5.5 |
| 异步 + 可取消 | 所有可能耗时的操作走 `LatestTaskRunner`，新请求取消旧请求 | NAVIGATION §3.2、SEARCH §2.3 |
| 不执行文件内容 | 预览按纯文本渲染，绝不解析 HTML/脚本 | NAVIGATION §4.2 |
| 不跟随符号链接 | 搜索与树遍历均不穿透重解析点 | SEARCH §3.3 |
| 不做库（Libraries） | 与"栏+路径"模型冲突，用多栏/预设替代 | NAVIGATION §5.4 |
| 明确的失败优于静默降级 | 配置目录不可写、UAC 取消等场景都明确报错 | SETTINGS §5.5 |
| 强制安全项 | 永久删除确认不可关闭 | SETTINGS §5.4 |
| 自动折叠是临时状态 | 窗口变窄时的折叠不覆盖用户的显式开关 | NAVIGATION §5.1 |

## 5. 本轮审阅修正记录（2026-10-24）

设计初稿完成后做了一轮自查，修正以下问题：

| # | 问题 | 修正 |
| --- | --- | --- |
| 1 | 库功能定位模糊（"建议降优先级"） | 改为**明确不做**，补 4 条理由与替代方案 |
| 2 | 设置项数量自述不一致（"30+" vs "约 40 项" vs 实际 34 项） | 统一为实际值 34 |
| 3 | 窗格自动折叠按**窗口宽度**判断 | 改为按**内容区实际宽度**判断。四栏时窗口很宽但每栏很窄，按窗口宽度会误判 |
| 4 | 自动折叠直接改用户的显式开关 | 拆分为 `IsAutoCollapsed`（临时）与 `ShowPreviewPane`（用户设定），窗口变宽后恢复 |
| 5 | 预览"不缓存"会导致按住方向键连续读盘 | 增加 150ms 防抖 + 取消 + 结果校验（防竞态） |
| 6 | 搜索"边扫描边追加"与现有全量替换架构冲突 | 明确批量刷新策略（200ms/500 项），并说明为何不能逐项 `Add` |
| 7 | "设置即时生效"未区分代价 | 按 A/B/C 三档拆分，明确「显示隐藏文件」必须重枚举 |
