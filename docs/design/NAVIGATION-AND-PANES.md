# 功能设计：导航窗格、详情窗格、预览窗格

- 版本：v1.0 草案
- 日期：2026-10-24
- 状态：**仅设计，未实现**
- 前置阅读：[PRD §3.1 / §3.2](../PRD.md)、[SETTINGS.md](SETTINGS.md)

---

## 1. 为什么这三块要一起设计

它们都挂在**同一块窗口区域**上，且共享"当前选中项"这一输入：

```
┌──────────────────────────────────────────────────┐
│ 菜单栏                                            │
├────────────┬─────────────────────┬───────────────┤
│            │                     │               │
│  导航窗格   │      文件列表        │   预览窗格     │
│  (树)      │   (栏 × 标签)       │  (可选，右侧)  │
│            │                     │               │
├────────────┴─────────────────────┴───────────────┤
│ 详情窗格（可选，底部）                             │
├──────────────────────────────────────────────────┤
│ 状态栏                                            │
└──────────────────────────────────────────────────┘
```

分开设计会导致：谁占用宽度、谁先隐藏、树与列表如何联动，各自为政。因此合并为一篇。

## 2. 导航窗格（树）

### 2.1 节点类型

| 类型 | 来源 | 说明 |
| --- | --- | --- |
| **快速访问** | 固定项 + 最近使用 | 用户可固定文件夹；最近使用由本程序自己记录（不写系统） |
| **桌面** | `SHGetKnownFolderPath(Desktop)` | 展开为用户桌面下的文件夹 |
| **下载 / 文档 / 图片 / 音乐 / 视频** | 已知文件夹 | 与系统位置一致 |
| **此电脑** | 驱动器枚举 | 显示卷标、容量、可移动/网络图标 |
| **网络** | `WNetEnumResource` | 懒加载，失败时显示明确提示而非空白 |

> **库（Libraries）已决定不做**，理由见 §5.4。

### 2.2 懒加载与虚拟化

树的规模可能很大（网络邻居、深层目录），必须懒加载：

- 首次展开某节点时才枚举其子节点
- 枚举在后台线程，展开动画立即开始，子节点到达后填充
- 枚举失败（无权限/断网）→ 节点下显示**一个不可选中的错误项**，文字为具体原因

**性能约束**：树的展开状态在会话间持久化，但**不持久化未展开节点的子项**——否则启动时会把整棵树加载出来。

### 2.3 与文件列表的联动

| 交互 | 行为 |
| --- | --- |
| 单击树节点 | 焦点栏导航到该位置（当前标签） |
| `Ctrl+单击` | 在**新标签**打开 |
| 拖放文件到树节点 | 复制/移动该节点（复用现有 `DropPolicy`） |
| 拖拽悬停 600ms | 自动展开该节点（便于投放到深层目录） |
| 列表导航后 | 树中对应节点**自动展开并选中**（不滚动到视口外） |

> 最后一条是 Explorer 的行为，也是树最有价值的地方：用户始终知道"我在哪"。

### 2.4 显示与隐藏

- 菜单「视图 → 导航窗格」切换，快捷键 `Ctrl+Shift+E`（对齐 Explorer）
- 宽度可拖动，最小 140px，最大 40% 窗口宽
- 宽度持久化到设置
- **四栏布局下**：导航窗格属于**窗口级**（共享），不属于单个栏

## 3. 详情窗格（底部）

### 3.1 内容

随选中项变化：

| 选中状态 | 显示 |
| --- | --- |
| 无选中 | 当前目录的汇总：项数、总大小、"N 个文件夹，M 个文件" |
| 单个文件 | 名称、类型、大小、修改时间、创建时间、路径 |
| 单个文件夹 | 名称、类型、包含项数（异步统计）、路径 |
| 多个项 | "已选择 N 项"、总大小、类型分布（若全为同类则显示类型） |

### 3.2 关键约束

**统计必须异步且可取消**。计算文件夹大小或"包含项数"在大目录上可能耗时数秒：

- 选中后立即显示已知字段（名称/类型/路径）
- 大小与计数显示为"计算中…"，后台计算完成后填入
- 切换选中项时**取消**上一次计算（复用 `LatestTaskRunner`）
- 超过 2 秒未完成时显示"仍在计算…"并允许用户取消

### 3.3 显示方式

- 菜单「视图 → 详情窗格」切换，快捷键 `Alt+Shift+P`（Explorer 的 `Alt+P` 是预览窗格，详情窗格无默认键，此处自定义）
- 高度固定约 90px，内容单行两列布局
- 与预览窗格**可同时显示**（底部详情 + 右侧预览），与 Explorer 一致

## 4. 预览窗格（右侧）

### 4.1 支持的预览类型

| 类型 | 方式 | 说明 |
| --- | --- | --- |
| 纯文本（.txt/.log/.md/.json/.xml/.cs 等） | 自己读取 | 限制前 64KB，超出提示"文件过大，仅显示前 64KB" |
| 图片（.png/.jpg/.gif/.bmp/.webp） | WPF `BitmapImage` | 等比缩放到可用区域 |
| PDF | 暂不支持 | 显示元数据 + "无预览可用" |
| 其他 | 无 | 显示元数据（名称/类型/大小/修改时间） |

### 4.2 安全与正确性

- **绝不以任何方式执行文件内容**（不解析脚本、不加载 HTML）
- 文本按 UTF-8 读取，失败则回退到系统默认编码；仍失败显示"无法解码"
- 图片解码设上限（如 50MP），超限不解码，避免内存爆炸
- 读取失败（占用/权限）显示原因，不弹窗

### 4.3 交互

- 菜单「视图 → 预览窗格」，快捷键 `Alt+P`（对齐 Explorer）
- 宽度可拖动，最小 200px，最大 50% 窗口宽
- 多选时显示"已选择 N 项，无法预览"

**缓存策略（修正）**：不做内容缓存，但必须做**防抖与取消**，否则按住方向键浏览时会连续读盘：

| 机制 | 参数 | 原因 |
| --- | --- | --- |
| 防抖 | 选中变化后 **150ms** 才加载 | 键盘快速移动时只在停下后读一次 |
| 取消 | 新的选中立即取消上一次读取 | 避免旧内容覆盖新内容 |
| 结果丢弃 | 读取完成时校验"当前选中项是否仍是发起时的那个" | 防竞态 |
| 大小上限 | 文本 64KB、图片 50MP | 防内存爆炸 |

> 早期设计写的是"预览内容不缓存"，但那样每次选中变化都会读盘。防抖 150ms 已能消除绝大多数重复读取，
> 比引入缓存失效逻辑更简单可靠。

## 5. 跨功能的共同问题

### 5.1 空间分配优先级

窗口变窄时，谁先消失？规则（与 Explorer 一致）：

```
1. 先隐藏预览窗格（右侧）
2. 再隐藏详情窗格（底部）
3. 再收窄导航窗格（到 140px 为止）
4. 最后导航窗格也可隐藏
```

**实现方式（修正）**：不使用「窗口宽度 < 900px 自动隐藏」这类硬阈值。原因是：
四栏布局下每个栏的可用宽度远小于窗口宽度，按窗口宽度判断会在四栏时错误地保留预览窗格。

改为**按内容区实际宽度判断**：

- 内容区宽度（`LayoutHost.ActualWidth`）< 600px 时，预览窗格强制折叠
- < 400px 时，详情窗格强制折叠
- 折叠是**临时状态**（`IsAutoCollapsed`），与用户的显式开关（`ShowPreviewPane`）分离；
  窗口恢复宽度后自动展开回用户设定的状态

> 这个分离很关键：若直接把用户的 `ShowPreviewPane` 改成 `false`，用户拉宽窗口后预览窗格不会回来，
> 看起来像"设置丢失"。

### 5.2 四栏下的行为

| 元素 | 归属 | 说明 |
| --- | --- | --- |
| 导航窗格 | 窗口级 | 四栏共享一个树；点击作用于**焦点栏** |
| 详情窗格 | 窗口级 | 显示**焦点栏**的选中项 |
| 预览窗格 | 窗口级 | 同上 |

> 不按栏各配一套：四栏 × 三个窗格会让可用面积归零。这是与"每栏独立标签"不同的取舍，需要在 UI 上让用户明白"这些是窗口级的"。

**宽度分配细则**：预览窗格固定宽度（默认 320px），导航窗格固定宽度（默认 220px），
**剩余空间全部分配给栏区域**。不按比例分配，因为固定侧栏 + 弹性主区更符合直觉，
也避免窗口缩放时侧栏跟着变宽。

### 5.3 焦点变化的联动

焦点栏切换（`F6`）时，详情/预览窗格内容随之切换。若目标栏有选中项，立即显示；否则显示该栏当前目录的汇总。

### 5.4 库（Libraries）：明确不做

**决策：不实现库功能**（2026-10-24 确认）。导航窗格中不出现「库」节点，
不解析 `.library-ms`，不提供多路径聚合视图。

理由：

| # | 理由 |
| --- | --- |
| 1 | **与产品定位冲突**：本产品以「栏 + 标签 + 路径」为一等公民，用户直接面向真实路径。库是"虚拟聚合视图"，会引入第二套"位置"概念，使导航模型复杂化 |
| 2 | **平台已弱化**：Win10/11 资源管理器默认折叠库，微软自身不再推广；Win7 用户迁移后使用率低 |
| 3 | **正确性成本高**：一个文件可能出现在多个库路径下，聚合视图需要处理去重、跨卷排序、以及"删除时到底删哪个物理副本"的歧义 |
| 4 | **替代方案已足够**：常用位置（桌面/下载/文档/图片/音乐/视频）+ 快速访问固定项 + 标签页，已能覆盖"快速到达常用目录"的原始需求 |

**替代路径**：若用户需要"把多个目录当一组看"，建议用**多栏布局**（每栏一个目录）或**布局预设**，
这是本产品已有的能力，且语义比库更清晰。

> 本决策同时影响：PRD `NAV-06` 标记为取消；`SRC-04`（搜索范围含"库"）同步移除该选项。

## 7. 验收标准

| # | 标准 |
| --- | --- |
| 1 | 树节点懒加载：启动时不枚举未展开节点，展开 1000 项目录不冻结 UI |
| 2 | 树与列表双向联动：导航后树自动定位；点树列表跟随 |
| 3 | 详情窗格选中文件夹时，大小/计数异步计算且可取消，切换选中立即取消上一次 |
| 4 | 预览窗格对 10MB 文本只读前 64KB，不卡顿 |
| 5 | 预览窗格绝不执行内容（文本按纯文本渲染） |
| 6 | 窗口变窄时按 §5.1 优先级自动隐藏，且不覆盖用户手动选择 |
| 7 | 四栏布局下三个窗格为窗口级，焦点切换时内容跟随 |
| 8 | 三个窗格的显示状态与宽度在重启后恢复 |

## 8. 实施建议（拆分顺序）

| 阶段 | 内容 | 理由 |
| --- | --- | --- |
| 1 | 详情窗格 | 依赖最少（只需选中项），能立刻改善可用性 |
| 2 | 导航窗格（先只做此电脑+已知文件夹） | 树的懒加载是主要复杂度，先做最小可用 |
| 3 | 预览窗格（先只做文本+图片） | 独立性强，可并行 |
| 4 | 树的高级节点（网络）、拖放联动 | 依赖前序稳定 |
