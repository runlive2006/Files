## 1. 产品定位

一句话：**用现代工程重做 Windows 7 资源管理器，把它的功能全部覆盖，并加上多栏（分屏）浏览能力。**

Windows 7 的资源管理器是一代经典：**Ribbon**（首次取代菜单栏）、**库（Libraries）**、堆叠（Stacks）、收藏夹、面包屑导航、详情/预览窗格、搜索筛选器、复制冲突对话框。它把桌面文件管理的交互范式定型了。但它止步于此：**没有真正的双内容栏**（树 + 内容区不算双栏，那是 Vista 就有的）、大目录性能差、且随系统一同停止支持。

本项目取 Win7 Explorer 的功能集为**验收基线**，把"多栏"（这一能力在 Windows 内置资源管理器中始终缺失，仅 Total Commander 等第三方工具有）扩展到**左右分栏 / 上下分栏 / 田字四栏**，并把性能与可扩展性做成 Win7 从未做到的水平。

### 1.1 目标用户

| 画像 | 关键诉求 | 对应功能 |
| --- | --- | --- |
| 重度文件管理者（开发、设计、资料整理） | 频繁在多个目录间搬运文件，厌恶来回切标签 | 多栏、跨栏拖放、栏间复制 |
| 从 Win7 迁移的老用户 | 界面逻辑熟悉，不愿重学 | Ribbon、面包屑、库、详情窗格 |
| 低配/老硬件用户 | 内存占用低、老盘（HDD）不卡死 | 虚拟化、异步 IO、内存预算 |

### 1.2 非目标（明确不做）

- ❌ 不做 FTP / SFTP / WebDAV 挂载（M5 后另议）
- ❌ 不做压缩包内浏览（zip 虚拟文件夹）—— M4 之后的可选特性
- ❌ 不做云盘（OneDrive/Dropbox）状态徽标 overlay
- ❌ 不做插件市场 / 第三方扩展运行时（安全模型成本过高）
- ❌ 不做 Win7 外观高保真还原（Aero 玻璃）——仅还原**功能与交互逻辑**
- ✅ **做多标签页**：与多栏并存（D1 已确认两者都要），模型见 §2.2

## 2. 核心概念：栏与标签（Pane × Tab）

**两层容器：布局树决定"分几个栏"，标签页决定"每栏里开几个位置"。** 一个窗口 = 一棵 1..4 个叶子的布局树；每个叶子（栏）持有一个标签组；每个标签是一个完全独立的浏览实例。

这样解决了两种范式的冲突：**栏**用于"同时看多个位置"（搬运、对比），**标签**用于"同一栏内快速切换上下文"（临时查资料、跳回原处）。二者不是二选一。

### 2.1 布局模型（栏）

| 布局 | 说明 | 快捷键 |
| --- | --- | --- |
| `Single` | 1 栏 | `Ctrl+1` |
| `HSplit` | 左右分栏（垂直分隔条） | `Ctrl+2` |
| `VSplit` | 上下分栏（水平分隔条） | `Ctrl+3` |
| `Quad` | 田字四栏（2×2） | `Ctrl+4` |

四栏的**生成规则**（关键设计决策，避免"四栏从哪来"的困惑）：

- 由 `HSplit` 按 `Ctrl+4` → 每个半区各自垂直分裂，形成 2×2；
- 由 `VSplit` 按 `Ctrl+4` → 每个半区各自水平分裂，形成 2×2；
- 由 `Single` 按 `Ctrl+4` → 先分裂为 `HSplit`，再各自垂直分裂；
- 新栏**继承来源栏的活动标签路径**，但立即独立导航。

回到 `Ctrl+1` 时，保留焦点栏（及其全部标签），其余栏连同其标签一起关闭。**若被关闭的栏中有未完成的操作或未保存的布局改动，须先确认**（见 §5.7）。

### 2.2 标签页模型（栏内）

每栏是一个标签组，标签数 `1..N`（软上限 20，超出时提示并可继续）。

| 操作 | 快捷键 | 是否 Explorer 原生 |
| --- | --- | --- |
| 新建标签（复制当前路径） | `Ctrl+T` | ✅ 是 |
| 关闭当前标签 | `Ctrl+W`（仅剩 1 个标签时等同于关闭该栏） | ✅ 是 |
| 下一个 / 上一个标签 | `Ctrl+Tab` / `Ctrl+Shift+Tab` | ✅ 是 |
| 在栏间循环焦点 | `F6` / `Shift+F6` | ✅ 是（Explorer 用 F6 循环窗格） |
| 关闭其他标签 | 标签右键菜单（不占全局快捷键） | — 扩展 |
| 恢复最近关闭的标签 | `Ctrl+Shift+T` | — 扩展 |
| 复制标签 / 移动到另一栏 | 标签拖放 / 右键菜单 | — 扩展 |
| 标签列表（溢出时下拉） | 标签条右端按钮 | — 扩展 |

设计约束：

- **`Ctrl+Tab` 归标签页，栏间切换用 `F6`** —— 二者不能共用，否则在四栏 + 多标签下会不可预测。
- 标签条仅在标签数 ≥2 时显示，单标签时隐藏，避免为 1 个标签浪费 24px 高度（**这一点直接关系 §5.1 的可用内容区与视觉密度**）。
- 标签拖放跨栏：拖到目标栏标签条 = 移动；拖到目标栏内容区 = 移动该标签的当前目录到该栏打开。
- 标签标题显示文件夹名，悬停显示完整路径；同名标签以父目录名区分（`项目\src` 与 `备份\src`）。
- 关闭窗口时若有 N 个标签，恢复会话时全部还原（见 §2.5）。

### 2.3 栏与标签的状态归属

| 归属层级 | 持有状态 |
| --- | --- |
| **标签（Tab）** | 当前路径、选择集、列排序/分组、视图模式、滚动位置、筛选器、历史栈（后退/前进，深度 50）、搜索状态 |
| **栏（Pane）** | 标签列表、活动标签索引、分隔条比例 |
| **窗口（Window）** | 布局树、窗口几何与所在显示器、Ribbon 折叠状态 |

视图模式按**标签**独立（允许同栏内不同标签用不同视图），这是与 Win7 一致的语义（Win7 的视图设置本就按文件夹记忆）。

### 2.4 栏间交互（本产品的核心增量价值）

| 交互 | 行为 |
| --- | --- |
| 跨栏拖放 | 源栏选中项拖到目标栏视口 → 释放即移动；按住 `Ctrl` → 复制；按住 `Shift` → 强制移动；跨卷自动降级为复制并显示卷标提示 |
| 跨栏悬停回焦 | 拖拽悬停某栏边缘 500ms，该栏自动向父目录/子目录滚动展开（Explorer 式的"拖到树上自动展开"） |
| 焦点栏指示 | 焦点栏分隔条与标签条 1px 强调色描边；`F6` 在栏间循环 |
| 标签跨栏移动 | 拖标签到另一栏的标签条 |
| 栏级同步 | 可锁定"相邻栏跟随本栏父目录"（镜像模式，做对比时极有用） |
| 拖出窗口 | 拖文件出窗口 → 交给系统 Explorer（真实 shell 拖放协议，非自绘） |

### 2.5 布局与标签持久化

布局树、每栏的标签列表与活动标签、每标签路径、列宽、分隔条比例写入工作区文件（`%APPDATA%\Files\workspace.json`）。启动恢复上次会话，含"打开时恢复各栏与标签"开关。窗口几何按 DPI 感知存储，跨显示器移动时记录所在 monitor。

该文件同时是**设置漫游与导入导出**的载体之一（见 §5.5）。

#### 3.4.1 搜索语法（对 Win7 AQS 的兼容子集）

```
ext:.log        kind:picture    size:>10mb    size:1kb..1mb
datemodified:thisweek   type:folder   文件名子串（不区分大小写，按当前区域设置排序规则）
组合：kind:picture size:>1mb ext:.png  （空格 = AND）
取反：~ext:.tmp                       引号：短语 "项目 周报"
```

不支持 Win7 AQS 的 `structuring:`、`store:`、`removabledrive:` 等冷门属性；未识别的属性名前缀按普通文本处理（**避免静默零结果**）。

| TAB-05 | 关闭未保存/操作中的标签时确认 | P0 | §5.7 |
| TAB-06 | 标签固定（pin）与整栏标签组保存为布局 | P2 | 与 PANE-06 复用同一套序列化 |

> **性能约束**：标签是"状态容器"，不是"预先创建的视图"。非活动标签**不得**保留可视化树与项容器，只保留状态（路径、选择、滚动偏移、排序）。否则 4 栏 × 20 标签会瞬间击穿 §5.1 的内存预算。

## 5. 非功能需求

### 5.1 性能预算（验收线，D1-3 已确认）

| 指标 | 目标 | 测量方法 | 红线（不合格） |
| --- | --- | --- | --- |
| 冷启动到首屏可交互 | ≤ **400ms** | ETW 事件打点，`main` 入口→首栏渲染完成 | > 800ms |
| 热启动 | ≤ **150ms** | 同上 | > 300ms |
| 工作集（单栏，1000 项） | ≤ **90MB** | `Environment.TickCount` + `GetProcessWorkingSetSize` | > 150MB |
| 工作集（四栏，各 1000 项） | ≤ **150MB** | 同上 | > 250MB |
| 工作集（四栏 × 5 标签，各 1000 项） | ≤ **220MB** | 非活动标签只留状态，不留视图 | > 350MB |
| 切换标签 | ≤ **80ms** | 从点击到内容可滚动 | > 200ms |
| 10 万项目录滚动帧率 | ≥ **58fps** | 帧计时器采样，1080p 桌面，SSD | 出现 >50ms 单帧 |
| 进入 10 万项目录 | 首屏 ≤ **600ms**（占位渲染） | 先出可滚动空行，属性惰性填充 | 主线程阻塞 > 1s |
| 图标/缩略图加载 | 不阻塞滚动 | 队列 + 可取消 | 滚动中出现图标风暴 |
| 内存增长（1 小时遍历 500 目录） | ≤ **30MB** | 定时采样 | 单调增长（泄漏） |
| 空闲 CPU | ≤ **1%** | 30s 平均 | 持续 >5% |

> **HDD/网络盘单列**：机械盘上"进入目录"允许升级到 2s 首屏，但必须仍是占位渲染 + 后台填充，绝不允许 UI 线程等待 IO。
>
> **标签数量的内存模型**：每标签的"冷状态"（路径 + 选择 + 滚动 + 排序）目标 ≤ 2KB；20 标签 × 4 栏 ≈ 160KB，可忽略。真正昂贵的是视图与项容器，因此非活动标签必须释放视图（§4.2 性能约束）。

### 5.2 资源与稳定性

- 句柄数：稳态 < 500；目录枚举结束必须释放 `FindHandle`（用 `SafeFindHandle`）。
- 崩溃率：shell 扩展故障不得拖垮主进程（§6.6）。
- 未处理异常：写本地日志 + 恢复提示，不静默退出。

### 5.3 可访问性与本地化

- 中/英文界面，资源可外置；首次启动跟随系统区域。
- 全部 P0 功能键盘可达；Narrator 可读出列表项（`AutomationProperties`）。
- 高对比主题适配；字号跟随系统 DPI，不出现截断。

### 5.4 安全与正确性

**默认以中等完整性运行，管理员权限按需显式获取。** 这是"提供管理员入口"与"不牺牲安全"之间的取舍方案。

| 场景 | 行为 |
| --- | --- |
| 常规浏览/操作 | 中等完整性运行。需要提权的单次操作由 `IFileOperation` 自行触发 UAC |
| 用户主动要求 | 提供「**以管理员身份重新启动**」命令（Ribbon / 命令面板 / 设置页），通过 `ShellExecute(..., "runas", ...)` 重启自身并**传递当前工作区状态**（布局树 + 标签），重启后无缝恢复 |
| 已在管理员模式运行 | 标题栏与状态栏显示明确的"管理员"标识，**不允许用户忽略**当前权限状态 |
| 管理员模式下的第三方 Shell 扩展 | **自动禁用**（见下方说明） |

管理员模式的额外约束：

1. **重启时只传工作区状态文件路径，不传任意命令行参数**，避免被利用做提权跳板。
2. 管理员模式下**自动关闭第三方 Shell 扩展**（CTX-02）与"拖入拖出到 Explorer"的进程外拖放，因为它们会把高完整性令牌暴露给第三方 DLL。UI 必须显式提示这一降级，而不是静默失效。
3. 不写入系统目录、不修改注册表 `Run` 键、不安装 shell 扩展。**"以管理员身份运行"是运行态选项，不是安装态要求**。
4. 提权失败（UAC 取消、策略禁止）给出可操作的指引，不静默降级。

其他正确性要求：

- 路径处理：长路径（`\\?\` 前缀）、UNC、保留名（`CON`/`NUL`）、尾随空格与点、大小写不敏感、Unicode 正规化 —— 全部有专门测试集（见 DEV-PLAN 测试矩阵）。
- 删除/覆盖操作**永不**因解析歧义扩大作用范围；通配与批量操作必须显式预览。

### 5.5 设置、漫游与导入导出

**设置模型**分三层，优先级由低到高：`内置默认` → `机器级`（`%PROGRAMDATA%\Files\settings.json`）→ `用户级`（`%APPDATA%\Files\settings.json`）。

| 能力 | 要求 |
| --- | --- |
| 漫游 | 设置目录可重定向到用户指定的同步位置（如 OneDrive 文件夹）。**只漫游设置，不漫游工作区布局**（布局含绝对路径，跨机器无意义），二者可分别开关 |
| 导入 / 导出 | 单文件 `.filesconfig`（ZIP 容器：`settings.json` + `keybindings.json` + `layouts/*.json`），带 `schemaVersion` 与迁移链 |
| 迁移 | 旧版本 schema 自动升级；**无法升级时拒绝导入并保留原配置**，不得部分写入 |
| 原子写 | 所有设置写入用临时文件 + `File.Replace`，断电不产生半个 JSON |
| 冲突 | 导入时若与现有设置冲突，提供"合并 / 覆盖 / 另存为"三选，默认**合并** |
| 便携模式 | 若程序目录存在 `files.portable` 标记文件，则设置写入程序目录下的 `data/`，不碰 `%APPDATA%` |
| 重置 | 提供"恢复默认设置"，且可只重置单个分组（外观/快捷键/文件操作/隐私） |

> 设置项本身必须**可枚举、可描述**（名称、类型、默认值、分组），因为导入导出、命令行覆盖、以及未来的策略管控都依赖这份元数据。禁止用散落的静态字段存设置。

### 5.6 快捷键约定（跟随 Windows Explorer）

原则：**凡是 Explorer 已有的操作，键位与 Explorer 完全一致**；Explorer 没有的能力（多栏、标签扩展、命令面板）才自定义，且自定义键不得抢占 Explorer 键位。

| 类别 | 键位 |
| --- | --- |
| 导航 | `Alt+←` / `Alt+→` / `Alt+↑` / `Alt+D`（地址栏）/ `Backspace`（后退） |
| 标签 | `Ctrl+T` / `Ctrl+W` / `Ctrl+Tab` / `Ctrl+Shift+Tab` / `Ctrl+Shift+T`（恢复，扩展） |
| 栏 | `Ctrl+1..4`（布局）/ `F6`、`Shift+F6`（栏间循环，与 Explorer 的窗格循环一致） |
| 文件操作 | `Ctrl+C` / `Ctrl+X` / `Ctrl+V` / `Del` / `Shift+Del` / `F2` / `Ctrl+Shift+N`（新建文件夹）/ `Alt+Enter`（属性） |
| 视图 | `Ctrl+Shift+1..5`（视图模式）/ `Ctrl+滚轮`（图标大小）/ `Ctrl+Shift+E`（展开导航树）/ `Alt+P`（预览窗格） |
| 选择 | `Ctrl+A` / `Ctrl+I`（反选）/ `Ctrl+Space`（切换选中） |
| 搜索 | `Ctrl+E` / `Ctrl+F`（聚焦搜索框）/ `F3`（下一个匹配） |
| 应用 | `F5`（刷新）/ `F11`（全屏）/ `Ctrl+P`（命令面板，扩展）/ `Alt`（Ribbon 提示键） |

全部键位可通过 `keybindings.json` 重映射；**重映射冲突时以用户显式配置为准，并在设置界面标红冲突项**。若用户把 Explorer 键位改掉，UI 中所有菜单项与提示必须同步显示新键位（不允许硬编码显示文本）。

### 5.7 会话恢复与关闭确认

- 正常关闭：保存布局树 + 各栏标签 + 各标签路径，写入 `workspace.json`（原子写）。
- 异常退出：下次启动检测到未标记为"正常退出"的会话，提示"上次未正常退出，是否恢复"，并提供"以安全模式启动"（单栏、不恢复标签、禁用扩展）。
- 关闭有操作进行中的标签/栏/窗口：必须提示，且提示中说明**具体还有几个操作在跑**，不可只弹"确定吗"。
- `workspace.json` 损坏：不阻塞启动，降级为默认单栏并保留损坏文件副本（`.corrupt`）供排查。

## 6. 架构决策要点（非实现细节，但约束产品承诺）

### 6.1 分层

```
Files.App (WPF 视图/交互)  →  Files.Core (用例/服务/模型)  →  Files.Interop (Win32/COM)
                                    ↑
                        所有平台调用只在 Interop 层，Core 可脱离 UI 单测
```

`Files.Core` 必须**能在没有 WPF 的情况下跑完全部用例**（含目录枚举、搜索、操作队列）。这是"能在 CI 上测"的前提，也是未来若换 WinForms/其他前端的保险。

### 6.2 数据流：标签 = ViewModel，视图 = 虚拟化控件

每个标签一个 `TabViewModel`（对应 §2.3 的 `TabState`），持有 `IReadOnlyList<EntryRow>` 的**可增量更新**集合。`PaneViewModel` 只负责标签集合与活动标签，不持有条目数据。视图只绑一层扁平集合，禁止在 XAML 里放格式化转换器（见 §6.5）。

非活动标签的 `TabViewModel` 保留状态但**不持有视图与项容器**；切换时按状态重建视图（目标 ≤80ms）。

### 6.3 属性填充策略（决定"10 万项不卡"的成败）

Win7 Explorer 的卡顿主因之一是同步取属性。本产品的强制策略：

1. 枚举只从 `FindFirstFileEx`/`WIN32_FIND_DATA` 拿**必需字段**（名称、属性、大小、mtime），一次系统调用即得，**零额外 IO**；
2. 首屏立刻渲染这些字段（此时扩展名列可能显示"…"）；
3. 只对**视口内 ±3 屏**的项，用后台队列补齐扩展属性（文件类型名、作者、分辨率等）；
4. 图标/缩略图同队列，**带优先级**：可见区 > 预取区；离屏项请求**取消**而非完成；
5. 图标按 `(路径 + 系统 DPI 刻度 + 请求尺寸 + 是否快捷方式)` 做键的 LRU 缓存，上限 **2000 个**，超出淘汰；
6. 同一扩展名共享图标位图引用（`.png` 一万次只解码一次）。

> 反模式（CI 静态检查阻断）：在列表绑定的 getter/转换器里调用 `Icon.ExtractAssociatedIcon`、`FileVersionInfo.GetVersionInfo`、`new FileInfo(...)`。

### 6.4 文件操作：必须走 Shell COM，而不是自实现

本产品**不自己写复制循环**，一律使用 `IFileOperation`（`FileOperation` COM 对象）：

| 收益 | 说明 |
| --- | --- |
| 性能与正确性 | Shell 内部的复制引擎处理 ACL、替代数据流、符号链接/重解析点、稀疏文件、硬链接语义 |
| 进度与冲突 | `IFileOperationProgressSink` + `SetOperationFlags` 原生提供统一进度与冲突处理 |
| 权限 | 自动触发 UAC 提权，无需自实现 |
| 回收站 | `FOF_ALLOWUNDO` 正确进回收站并保留"删除日期/原位置"（NAV-10 依赖此项） |
| 跨卷 | 系统级正确降级为复制 |

代价：interop 工作量大（COM vtable 手写、进度回调封送）。这是**必须付的成本**，自实现复制在 1.0 一定会在某个边界（长路径、重解析点、NTFS 流）上出错。

约束：
- 进度对话框**聚合整批操作**，不是每文件一个；
- 冲突必须一次性枚举完再呈现（`FOF_WANTNUKEWARNING` + 自定义 sink 收集），见 DLG-01；
- 取消必须在 200ms 内响应（`IFileOperation::Cancel` 语义 + sink 检查点）。

### 6.5 UI 性能工程约束（写进 CI 规则）

1. **禁止值转换器**做显示格式化；`EntryRow` 暴露预格式化字符串属性，在数据变更时算一次。
2. 列表使用 `VirtualizingStackPanel` + `IsVirtualizing=True` + `VirtualizationMode=Recycling`。
3. `ScrollViewer.CanContentScroll=True`（**项级**虚拟化，像素级虚拟化会实例化全部容器）。
4. 模板中避免 `Opacity`/`DropShadowEffect`/`BlurEffect`：这些会强制离屏渲染并摧毁滚动帧率。
5. 动画只动 `Transform` 与 `Opacity`（GPU 合成路径）；绝不动 `Width/Height/Margin`（触发布局）。
6. 绑定路径不超过 2 层；优先 `x:Bind` 不适用的场景用编译期 `DependencyProperty`。
7. 排序/分组在后台线程产出结果数组，UI 线程只做一次集合替换（用 `CollectionView` 或自带 `IComparer`，**不要**边滚边排）。
8. 大目录禁止 `ObservableCollection.Add` 逐项触发通知；用批量重置或增量区间通知。

### 6.6 Shell 扩展隔离

`IContextMenu3` 等第三方扩展在**独立子进程（64 位 + 可选 32 位）**中加载枚举，菜单序列化后回传主进程；主进程只调用被转发的 `InvokeCommand`。子进程崩溃 → 只丢这栏扩展项，主窗口不受影响。默认关闭，用户在设置里逐类开启。
