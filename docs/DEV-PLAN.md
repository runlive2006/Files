- 版本：v0.3（**重排开发顺序**，以"工作流完整度"替代原里程碑线性推进）

## 0. v0.3 重排说明（本版核心变更）

### 0.1 为什么重排

v0.2 采用 `M1 单栏 → M2 多栏 → M3 Shell 化 → M4 Ribbon → M5 打磨` 的线性推进。
实际开发后发现这个顺序有两个问题：

1. **里程碑编号与真实优先级脱节**。原计划把"面包屑"排在 M1.7、"`IFileOperation`"排在 M3，
   但前者是导航基础交互、后者关系到数据安全，二者都远比其他 M1 任务重要。
2. **"完成度"无法用里程碑衡量**。例如 M2 标称完成多栏，但导航窗格、详情窗格、
   搜索这些 Win7 Explorer 的标志性区域当时完全缺失——用户打开程序仍会认为"这不是资源管理器"。

### 0.2 新的排序依据

改为按 **"用户能否完成一次完整工作流"** 排序，分四个层级：

| 层级 | 判据 | 说明 |
| --- | --- | --- |
| **L1 能打开、能看见、能找到** | 打开任意位置、看到正确的文件、找到想要的 | 缺任何一项，程序不可用 |
| **L2 能操作、不出错、不丢数据** | 复制/移动/删除正确，大目录不卡死 | 缺任何一项，用户不敢用 |
| **L3 能顺手、符合预期** | 交互细节对齐 Win7、设置生效 | 缺了是"能用但难用" |
| **L4 能交付、能维护** | 安装包、签名、本地化、可访问性 | 缺了无法发布 |

这个排序的好处：**任意时刻停下来，程序都处于"可用的完整状态"**，
而不是"功能做了一半、用不了"。

## 3. 重排后的执行顺序

### 第一波：补完 L1 + L2 核心（让程序"看起来是资源管理器"）

| 顺序 | 任务 | 估时 | 理由 |
| --- | --- | --- | --- |
| 1 | **L1-4 搜索结果路径列** | 0.5d | 工作量最小，直接解决"搜到一堆同名文件分不清" |
| 2 | **L2-3 回收站视图** | 3d | 删除已能用，但无法还原——数据安全闭环的缺口 |
| 3 | **L2-4 属性对话框** | 3d | 文件操作的最后一块常规能力 |
| 4 | **L1-5 网络位置** | 2d | 补齐"能打开任意位置" |
| 5 | L2-5 搜索结果虚拟化 | 1d | 上万条结果场景 |

**为什么这样排**：搜索路径列只有 0.5 天，顺手先做掉，避免"小项永远排在最后"；
回收站与属性对话框是 L2 核心，和"敢不敢用"直接相关，必须在 L3 之前完成。

### 第二波：L3 设置接线（"能用但难用"→"顺手"）

| 顺序 | 任务 | 估时 | 理由 |
| --- | --- | --- | --- |
| 6 | `FileOps.*` + `View.*` 接线 | 1.5d | 用户改了设置没反应，是信任问题 |
| 7 | `Startup.SingleInstance` | 1d | 从资源管理器"用本程序打开"的必要条件 |
| 8 | `Panes.*` + `Perf.*` 接线 | 1d | 收尾 |
| 9 | 设置导入 / 导出 | 1d | 换机迁移 |

## 4. 关键风险与预案

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| 网络位置枚举卡死 | 断网或共享不可达时界面冻结 | 必须在后台线程 + 硬超时；失败静默降级 |
| 回收站视图需 Shell 命名空间 | 可能需 `IShellFolder` interop | 先调研：若回收站无可用本地路径，评估工作量后再决定 |
| Ribbon 工作量超预期 | 拖累整体进度 | 已暂缓，不进 1.0 关键路径 |
| 第三方 Shell 扩展崩溃宿主 | 可能导致本程序崩溃 | 独立进程宿主，1.0 后 |

## 5. 里程碑重定义

原 M1/M2/M3/M4/M5 的线性阶段划分**不再作为执行口径**，改为按上述四波推进。
但保留"可运行交付物"的约定：每一波结束都应有一个可运行、可验证的版本。

| 版本 | 内容 | 相当于原计划 |
| --- | --- | --- |
| Alpha-1（当前） | L1 + L2 核心已完成，含面包屑/导航树/详情/搜索/云盘/`IFileOperation`/虚拟化 | 原 M1+M2+M3 大部分 |
| Alpha-2 | 第一波完成（搜索路径列、回收站、属性、网络位置） | — |
| Beta-1 | 第二波完成（设置全部接线） | 原 M4 前 |
| Beta-2 | 第三波完成（交互细节） | 原 M4 |
| RC → 1.0 | 第四波完成（安装包、本地化、可访问性） | 原 M5 |

## 7. 本机构建注意事项

受限环境需 `-m:1 --disable-build-servers`；`dotnet test` 的 VSTest 目标与
.NET 10 SDK + Microsoft.Testing.Platform 不兼容，测试走 `scripts/test.ps1`。

脚本使用 PS7 语法，请用 `pwsh` 而非 `powershell.exe`（5.1 无法解析部分写法）。
